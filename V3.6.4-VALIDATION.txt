Fara Xray / 3x-ui custom v3.6.4 validation report
=================================================

Release base
------------
- Source tree was created from the complete 3x-ui-v3.6.0-source.zip archive.
- A local baseline commit was created before modifications.
- v3.6.1, v3.6.2, and v3.6.3 source trees were not used.
- internal/config/version is 3.6.4.

Implemented
-----------
- Subscription maintenance notice and fallback-only modes for RAW, Xray JSON, and Clash/Mihomo.
- Durable one-minute client traffic buckets and recent IP history.
- Detailed per-client report API and responsive report UI.
- Subscription app and operating-system reporting.
- Related Host reporting, busiest usage hour, anomaly history, and renewal/change history.
- Detection of sudden spikes, sustained per-minute high traffic, and possible subscription sharing.
- Configurable alert, temporary disable, or dedicated limited-inbound reaction.
- Automatic restore, rollback on failed throttle attachment, action cooldown, and manual-change safeguards.
- SQLite/PostgreSQL model registration and cross-database migration registration.
- OpenAPI, generated TypeScript/Zod schemas, and Persian/English translations.
- History migration when a client's email is renamed.

Static validation completed
---------------------------
- All Go source files parse successfully with go/parser.
- gofmt applied to all changed/new Go files.
- git diff --check passed.
- Persian and English translation JSON parses successfully.
- Generated OpenAPI JSON parses successfully and includes GET /panel/api/clients/report/{email}.
- OpenAPI TypeScript/Zod schemas were regenerated from the Go structs.
- Changed TypeScript/TSX files passed syntax checking; only unavailable dependency/module-resolution diagnostics remain in this offline environment.
- Regression tests were added for maintenance notice/fallback behavior, setting persistence/validation, OS detection, set comparison, and report aggregation.

Environment limitation
----------------------
- The source requires Go 1.26.5 and Node 24.
- This offline environment has Go 1.23 and Node 22 and cannot download the required toolchains or project dependencies.
- Full dependency-aware Go tests and the production Vite build therefore were not executed locally.
- The repository CI/release workflows use go.mod and .nvmrc and run the complete Go test and frontend build after the commit/tag is pushed.
